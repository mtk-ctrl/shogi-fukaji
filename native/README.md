# 深路・独立C++ルール研究 第5段階・連続王手千日手と逐手合法手照合（未採用）

**目的**：python-shogi 1.1.1 の疑似合法手生成・自玉王手除去・打ち歩詰め禁止を独立C++17で再現する。Engine未接続・研究用・既定OFF。

- `native/rules_probe.cpp` の `P <SFEN>` はC++独立の疑似合法手集合（盤上移動、成り、持駒打ち、二歩、行き所のない駒）。`H <SFEN>` はそれを独立王手判定と打ち歩詰め禁止で絞った**合法手集合**。いずれもソート済みUSIをカンマ区切りで1行出力。
- 既存 `C <b|w> <SFEN>` は指定側の王手、`R <SFEN>` は同一SFEN盤面・手番・持駒の4回反復、`Z` は履歴初期化。
- `tests/test_native_rules_probe.py` では固定の打ち歩詰め・非詰め特殊局面とseed固定の序盤・中盤到達局面について、Pythonの疑似合法手集合とC++ `P` の完全一致、C++ `H` の完全合法手集合の一致（Python補正なし）、王手・4回反復・異常入力を検査する。着手順は検証対象外。
- **新設**：`B <SFEN>`で局面を読み込み、`M <USI>`でC++の完全合法手検査後に着手・捕獲駒の持駒追加・成り・手番と手数を更新。`U`は直前の着手を取り消し、`S`は現在のSFEN、`F`は現在の局面の4回反復の有無を返す。`L`は状態保持中のC++合法手集合、`T`は反復の裁定（`none`未成立、`draw`通常千日手、`black_loses`先手連続王手による負け、`white_loses`後手連続王手による負け）を返す。裁定は直近4回の同一局面間の全着手について、王手をかけ続けた側を判定する。`B/M/U/S`は正規化SFENを返す。`Z`は履歴と状態を初期化。研究専用の可逆局面で、通常Engineは使用しない。
- **検証**：捕獲・成り・持駒打ちの固定局面、seed固定6系列×最大70手で全手のSFENと逆順undoをpython-shogi 1.1.1に照合。4回反復とundoの履歴復元を確認。さらにseed固定6系列×最大60手の各着手・全undo後にC++の状態保持中合法手集合とPythonを直接比較し、先手/後手連続王手・通常千日手の3種類を固定局面で区別、Pythonの王手・4回反復と照合する。
- **未実装**：連続王手千日手の独立裁定は研究実装済みだが、特殊局面・有限の到達局面に対する回帰検査であり、公式ルール全事象の形式的証明ではない。Engine統合、実戦速度/棋力測定は未実施。`H` は独立した合法手列挙の研究プローブであり、対局履歴や時間管理を備えた完全エンジンではない。**実戦エンジンへは未接続**。
- 速度の根拠にはこの標準入出力プロトコルのテスト所要時間を使用しない。正しさの検査を通過した後、同じ探索条件で専用の速度測定を行う。雲路正式版は変更しない。

再現：`python -m pip install -r requirements.txt && python -m unittest tests.test_native_rules_probe -v`（g++必須）。

## 第6段階：研究専用の独立処理時間測定（正式採用なし）

`Q <回数> <SFEN>` はC++の合法手生成を同一局面で繰り返し、合法手件数の総和と処理時間（ナノ秒）を返す。回数1〜5000に制限し、SFEN読込・標準入出力・コンパイル時間は計測対象外。
`native/benchmark_rules.py` はseed固定の32局面で、C++ `pseudo_moves(board,true)` とPython `list(board.legal_moves)` を各30回×3試行測定する。計測前に全合法手集合の完全一致を強制し、固定局面SHA、環境、各試行時間をJSON保存する。これは**言語実装別の合法手生成時間**であり、実戦の200ms探索・棋力・10倍の探索効率化とは異なる。研究エンジン未接続、既定OFF。専用requestを明示更新してGitHub Actionsで測定する。
