# 深路UCT：探索木解放費用を含む事前時間予約（研究候補、2026-10-29）

## 背景・目的
総時計ON・単一合法手走査ONの非計測12親ABBA（run40723952839）は、200ms超過が従来12/24から3/24へ減少したが、最大200.359msで硬い上限を達成していない。軽量PR#75/76で探索木の生成ノード数に伴い、関数return時の探索木解放が内部時計と呼出側時計の差を生むことを確認。持駒5835ノードの明示解放は最大0.9176msだった。計測付きの軽量値であり、200ms実測への外挿は未証明。

## 候補
`select_mcts(..., cleanup_aware_reserve=True)` の**明示ON時のみ**、次の探索反復を開始する直前に、残時間が「推定次反復時間＋推定探索木解放時間」以下なら反復を開始しない。探索反復終了後の従来予約判定にも解放費用を加える。従来の `reserve=max(3ms,1.5×最長反復)` はそのまま既定OFF経路で維持する。

- 推定次反復時間：`max(3ms,1.5×観測最長反復)`。
- 推定解放時間：`1ms + 0.25ms×(生成Node数/1000)`。PR#76の小標本より安全側に寄せた**仮説上の係数**であり、上限保証値ではない。
- 生成Node数は根ノード・根子と、実際に展開時に生成した子を加算する。合法手・選択手・探索評価・モデルは変更しない。
- 根準備だけで時間予算を使い切った場合、反復0で合法手を返す。終局時は従来どおり投了。未決着に勝ち/引分ラベルを付けない。
- PythonのGC/OS割込み/長い1反復/盤面復元確認/実メモリ管理により、**200ms硬い上限は保証できない**。木の解放を後回しにして見かけの時間を短縮する実装ではない。

## 検証範囲
合成時計で10ms/反復・40ms予算・解放予約10msを与え、従来3反復に対して候補2反復で止まることを検証する。根準備が50msかかり予算20msを越えた場合の反復0合法手、初期・王手・持駒・打ち歩詰・4回千日手・詰みの合法手と盤面復元、固定seed/固定反復の着手一致、入力検証を追加する。軽量CI成功と実局面200msの改善を混同しない。
