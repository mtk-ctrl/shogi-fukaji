# 実行・保存・再開

- 短い実装・検査は各AIの利用可能な実行枠で続行。予約確認・通知は[F01](F01_継続実行とタイマー.md)に従う。
- 大量対局・長いActionsの前に所有repoの有効run、同目的重複、利用可能runner、計算上限、容量・期限を確認。別目的runを止めず、runner使用率のために局数を増やさない。
- 本人から20ランナーの指定がある本対局では、独立した序盤ペアを20ジョブに分ける。指定の実行経路・本人限定データの受け渡し・実行枠を確保できないときは、変更前に本人へ理由と実行できる範囲を伝える。4並列や少数局に無断で切り替えない。計画上の並列上限と、実際に起動したジョブ数・最大同時稼働数を区別して報告する。
- D17は一つの逐次学習器を使う小規模実証。世代間の依存を守り、同じ研究状態へ同時書込みしない。経験生成の分散化は集約の正当性と効率を確認してから行う。
- workflowは明示起動・有限世代・時間上限・単一writer。定期実行や無制限再起動を追加しない。workflow一覧と検査を同期する。
- 正式NNUEの学習前重みは比較・復元用に内容SHA付きで不変保存する。学習後重み・optimizer・親・データも保存し、学習前後の直接対局比較を通過した場合だけ正式manifestを原子的に新重みへ切り替える。失敗・悪化・途中停止では学習前正式重みに戻す。別系統の研究latestを正式版への昇格元にしない。
- 正式USI、比較基準、既存成果を契約検査で保護。研究の巻戻しで正式版を変更しない。
- コード・文書・小規模実証はGitHub。大量棋譜・モデルはデータ保存先へ分離。Actions artifactは期限付きであり長期保存と呼ばない。自動移送の未実装を明記する。
- 重要な判断・失敗原因・検証・次の一手はGitHub `docs/decisions/` と該当D系文書に差分保存し、mainで読戻す。ROADMAPは現在地の案内。Addnessは保留中・過去Goalの参照のみ任意。
- ローカルcheckpointを永続保存と呼ばない。長いローカル研究では不変checkpointを本人限定Driveへ移し、ownerのみmetadata・再取得SHA・実復元を確認する。外部送信を行わない `fukaji.portable_resume.create_index` で、実行中の復旧点と停止済み引継ぎ点を区別する。引継ぎ点は元rootのexclusive lock取得とarchive/state一致が必須。元実行環境のsession IDだけを別環境の再開方法にしない（D27でのWork障害は歴史的事実）。
- 深路に存在しない雲路固有の検査をそのまま必須化しない。深路は scripts/check_fukaji_contracts.py と関連テストを使う。

## GitHub Actionsの失敗通知・費用監査

- Gmailの失敗通知は**その実行時点の記録**であり、現在のmainの不具合・研究失敗の継続を直接意味しない。通知ごとにrepo、workflow、run ID、runのcommit・branch、失敗job/step、ログの具体的例外を確認する。研究branchの失敗と現行mainの失敗は分ける。
- 同一症状のメールが多数ある場合は、個別通知をそのまま作業数に換算せず、**失敗署名（workflow・step・例外）**単位にまとめる。初回・直近の代表runと件数・影響範囲を残す。再実行を先に繰り返さず、まずログで原因を絞り、少量の再現試験を用意する。
- 失敗runより後に同条件の成功runがある、またはmain上で原因が修正済みの場合は「過去の失敗・修正確認済み」とする。ただし修正後の成功が同じ検査を通っていることを確かめ、成功メールの不在のみで障害継続と判断しない。逆にコード修正だけで未実行なら「未検証」とする。
- 棋譜合法性、盤面/千日手履歴、モデル・optimizer・データSHA、契約試験の失敗は研究結果の採用を停止し、入力データ・再現条件・出力を突き合わせて修復する。失敗した研究runを対局成功件数に混ぜない。再現できない旧ログの問題は現行の別研究へ無条件に適用しない。
- Action実行前に**課金対象のprivate/public runner差、月次利用枠・現在の利用量・課金上限、各jobのCPU数・見込み時間**を確認する。前月の100%利用通知を翌月の残量と混同しない。本人の追加課金承認なしに有料超過を許容しない。不要な定期起動・失敗の自動再試行・並列無駄撃ちを増やさない。
- 調査結果は「修復・再検証済み／未解決／過去の失敗／利用許可・課金など本人判断待ち」に分類し、深路の未解決事項は該当GitHub Issueまたは研究文書にrun ID・再開条件を記録する。重要な判断はGitHubの `docs/decisions/` またはD系へ差分記録。Gmailを既読・削除・一括アーカイブにすることで解決済みとみなさない。

## 本人限定Driveのフォルダ・世代保持（2026-11-03）

- D19〜D35の既存保存フォルダは同じFile IDのまま `20261101-20261103_深路NNUE研究成果物_D19-D35（継続保存）` に改名。リンクは維持。以後新しい研究D番号ごとに `YYYYMMDD_FUKAJI_Dnn_研究名` フォルダを分け、archive名にD番号・日付・進捗・owner-onlyを記す。
- **常時保護**：正式採用の各版・配布と復旧証跡、研究ごとの検証済み最終完全state、重要な開始前snapshot・独立系統、原棋譜と結果、optimizer、SHA、再開index。
- **実行中は直近N=2の中間checkpoint**に加え開始前snapshot・最後の安全な停止境界を最低保持。最終archiveのowner-only・再取得SHA・別領域実復元・必要原データと結果の一致・元writer停止を確認するまで途中版を保護。
- 完了済み研究の途中checkpointは確認後に[整理候補台帳](../operations/2026-11-03_Drive容量と保持候補.md)へ分類できるが、**本人の削除承認があるまで移動も削除もしない**。候補固有データやindexの依存がある場合は保護へ戻す。容量と検査根拠を記録する。
- Actions artifactは期限付き。AIに保存や再開を自動化する機能がなければ、有限Actions→GitHub D系・Drive本人限定保存→次回対話で読戻す。実際に実施していない自動移送を完了としない。

## 複数AIの競合防止
ChatGPT・Claudeで同一Rule。mainの最新commitと対象文書・Actions・別AIの研究writerを編集前/反映直前に照合。競合時はブランチ/PRを使い、古いmainを全文上書きしない。文書だけのpushもworkflowの`push.paths`を照合して研究処理・保存/復旧へ影響しないことを確認する。
