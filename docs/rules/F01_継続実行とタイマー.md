# 深路：継続実行・予約確認・再開（AI共通）

ChatGPT・Claude共通。製品名ではなく**長時間の自律実行、予約実行、通知、永続保存、再開**の実際に利用可能な能力で判断する。本人の「タイマー連鎖」要求（2026-10-30）は維持する。正式採用の委任ではない。

## 基本
読取・分析・設計・実装・短い検証は、同じ実行枠で結果を確認しながら続行する。commitや作業区切りだけを理由に後回しにしない。**実際に開始した**非同期runをその枠内で最後まで確認できないときだけ、run ID・開始時刻・進捗・完了条件を記録して単発の確認予約を使う。稼働runなし、本人判断待ち、安全停止なら予約を置かない。

## タイマー連鎖の定義
1. 次の具体的作業を実際に開始。
2. 同種実測・残量・queue・集計/保存に基づき、その作業の終了見込みを計算。
3. 同じ枠で完了確認できない外部runについて、利用可能な予約機能で終了見込みに対応する単発確認を設定。
4. 確認時に実結果と永続保存を読取り、次工程を開始。必要なら新しい見込みで単発予約を更新。

5分の作業を根拠なく1時間後の終了予定にしない。毎時/5分ごとの固定周期、実行中でない作業時間の見積りへの混入、予約制約を隠す時刻の水増しは禁止。予約できる時刻と終了見込みに差があれば、双方の時刻・差・機能制約を別々に記録。規則を迂回しない。

## 同等機能がないAIの代替
有限・明示起動のGitHub Actionsを使い、run ID・commit・計画SHA・結果・失敗をD系文書に記録。重い学習stateとoptimizerは本人限定Driveに保存し、owner-only・再取得SHA・実復元を検証。 `docs/decisions/` とD系へ次工程・再開条件・実行コマンドを残し、**次の対話**で別AIが読み直して再開する。予約実行や無人継続を実現したとは主張しない。

ローカル計算は同じ環境で完了と永続保存まで追う。別環境へは[D27](../D27_PORTABLE_RECOVERY_20261102.md)の停止確認・exclusive lock・state/archive一致・実復元を満たす `stopped_handoff` で引継ぐ。`recovery_checkpoint_only` は別writerの起動許可ではない。複数AIの同時書込みを禁止する。

## 確認・引継ぎ項目
| 状態 | 対応 |
|---|---|
| 短い作業やCIを今確認できる | 同じ枠で検査・保存・次工程 |
| 長い実runが稼働し今確認できない | run IDと終了見込みから単発予約（機能が使える場合のみ） |
| runはないが別の実作業は可能 | 予約なしで実行 |
| 環境喪失・安全拒否・本人判断待ち | 原因、保存済み証拠、停止範囲、再開条件を正本へ記録 |

引継ぎには実施済みcommit/run/成果、次作業・成功条件、作業状態、実run ID、終了見込みの根拠、予約実時刻、制約による差、同じ枠で続けられない理由を残す。登録成功/実発火/結果取得/次工程を分けて確認する。

## タイマー連鎖の完了ゲートと失敗時の処理（2026-11-08追記）

- **タイマー設定完了≠連鎖成功。** 予約IDが存在し有効なこと、予約実時刻、実発火、対象外部run全ページの結果取得、永続保存のSHA読戻し、事前基準による採否、次工程の実起動、次工程のETA算定、次の予約作成とそのID読戻しを段階ごとに証拠とともに記録する。
- 予約が発火した時点で対象runが稼働中なら、未完了を成果とみなさず、runner実測から残りを再計算し**次の単発確認を登録してから**終了する。予約を作れなかったなら理由と未接続状態を通知・正本記録する。
- 対象runが終了したら、原棋譜・model・optimizer・評価・全Release/コミットのSHAと事前採用条件を検証する。条件通過なら同じ枠内で正式採用CIと次世代1000局の実開始まで進める。次の長いrunが稼働したら、その終了見込みに合わせて単発を予約する。**次回やると書いただけ、結果を報告しただけでは連鎖継続ではない**。
- 実行環境に予約作成・GitHub書込みツールがない場合は、連鎖できないことを明示する。根拠のない時刻への予約や固定周期への置換、実際にはできていない後続工程の完了宣言は禁止する。
