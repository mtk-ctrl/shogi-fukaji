# D23：同じNNUEと基本探索をC++で実行する

2026-11-01。[D23 Goal](https://www.addness.com/goals/ec6c7957-dc24-412e-a6d6-4da1c93a16d5)。D21/D22の候補は採用せず、第11周NNUE ac2d9c51と基本q0を固定して、実装言語による効率差だけを調べる。

## 接続範囲

- `native/nnue_search_ffi.cpp` は既存独立C++合法手・反復履歴の処理を利用する。評価は呼出側が渡した2548×32のNNUE重み・biasだけ。G7の評価重み・研究手・外部評価値は使わない。
- 駒・持駒の入力、白視点の回転、clipped-ReLU、出力、詰み・通常千日手・連続王手の結果、基本alpha-beta・反復深化・順序ヒントはPython研究探索に対応させる。
- 捕獲/成りの一般的な着手順は既存の研究探索と同じ。静止探索は0のみ。玉相対型のテンソルを黙って切り捨てず明示拒否する。
- `NativeSelector` は1局分のC++状態と凍結モデルhandleを保持し、実着手だけを同期する。探索分岐はC++内部で完結。モデル途中変更・別履歴への切替を拒否し、失敗時に別の探索へフォールバックしない。
- C++は検索用局面をコピーし、RAIIで分岐を復元。Python側のSFEN・反復数とC++状態も終了時に検査する。モデル16個・実戦状態16個、履歴512手、探索深度64を上限とする。
- Python側の準備時間を差し引いた残予算をC++へ渡し、返却後の検証まで含む実思考時間を記録する。コンパイルは事前準備であり、思考時間へ混ぜない。合法手生成1回の途中を強制中断する設計ではなく、厳密な時間上限の保証とは区別する。
- 正式USI・既定モデル・比較基準は変更しない。研究オプションの明示指定で使う。

## 検証と測定

新規検査は両視点評価、特殊局面とランダム到達局面の固定深さ着手・評価・節点、通常/連続王手千日手、1ms打切り復元、異常handle/arch/重み変更/履歴拒否、リソース再利用、先後backend追従、生成/親screen/周期比較へのbackend伝播。

最初の初期局面深さ2は着手6i6h・276節点、評価差1e-13未満。Python117.77ms、C++14.63ms。ただし1局面の例であり、全体の速度・棋力とはしない。

全体663tests成功後、継続学習のbackend設定引継ぎを追加した関連検査を行う。実モデルの速度測定は同じ環境に他の検査を重ねない。

```bash
OPENBLAS_NUM_THREADS=1 python -m fukaji.native_nnue_probe --root build/d23-state
```

保存済みtrainの直近4局＋bootstrap4局から4時点ずつ計32局面。両側は同じ履歴を準備し、深さ2の着手・評価（1e-7以内）・節点完全一致を要求。順番を交互にして測る。測定用SFENと原棋譜のhashは本人限定状態内へ保存する。

続く新monitor8序盤先後16局、各手100ms指定、256追加手。両側同じ凍結モデル、q0、条件はbackendのみ変更。未決着を引分にしない。

```bash
python -m fukaji.online_compare --root build/d23-state --left ac2d9c51ceb2979f79be5363f3d1f45bac020bcc9d15d58a3fb67c96145e227f --right ac2d9c51ceb2979f79be5363f3d1f45bac020bcc9d15d58a3fb67c96145e227f --left-backend cpp_nnue --right-backend python --name d23-native-arena --seed 202611012400 --pairs 8 --movetime 100 --max-plies 256
```

同じbackendを双方に使う継続学習には、`online_cycle cycle --native-backend --quiescence 0` を明示する。これは生成・親比較・周期比較すべてへ伝播する。研究用の暫定更新と正式採用を区別する。実行結果は検証後に追記する。

## 初版32局面の照合結果

全32局面で深さ2の着手・節点数完全一致、最大評価差4.55e-13。平均Python209.147ms / C++110.939ms、中央値128.067ms / 45.886ms、平均時間比1.885倍。モデル重み・教師・探索結果を変えない高速化経路が成立した。

C++初版は末端でも全合法手を生成・整列しており、D19のPython経路の「合法手1つの存在だけを調べる」最適化を再現していなかった。次に同じ存在判定をC++へ接続し、同じ32局面の一致と追加速度を検査する。初版測定は別の不変報告として残す。

局所全663tests成功、backend伝播追加後の新規8tests・関連33testsと契約成功。新規の直接C++利用を含む全体CIはPRで確認する。
