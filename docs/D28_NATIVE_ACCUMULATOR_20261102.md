# D28：C++ NNUEを着手差分で計算する

[D28 Goal](https://www.addness.com/goals/0c586a46-a185-420c-967a-ce24ddc9e3cb)。評価の意味/NNUE重みを変えず、同じ時間に探索できる範囲を増やす研究。D26の固定400局へは適用しない。

## 独立backend

従来nativeは葉で全駒/持駒のaccumulatorを再計算する。新backendは根で両視点を構築し、移動元/先の駒と変わった持駒特徴だけを加減する。各枝はaccumulatorを保存し、通常終了/timeout/例外で盤面/履歴とともに復元する。

`native/nnue_accumulator_ffi.cpp`は既存の凍結C++をincludeし、別のFFI関数を公開する。旧ファイルは変更しない。`fukaji.native_accumulator.AccumulatorSelector`は明示指定のみ。合法手/終局/反復深化/手順序/alpha-beta/NNUE tensor/leaf clippingは同じで、古典評価を葉に混ぜない。標準backend/正式USI/配布モデル変更なし。

## 事前に固定した診断

第15周ae53ce0dの同じNNUE、trainのbootstrap16＋第15周16の計32局面を対局結果と独立に抽出。monitor/auditは使わない。CPU5に固定し、現在の400局worker0..3/writer4と分離。深さ2は各局面ABBAABBA、同100msはABBA。着手/評価/節点/評価回数一致、固定深さ速度1.10倍以上を次の統合確認へ進む基準にする。強化の採用基準ではない。

| 指標 | 全再計算 | 差分計算 |

| 深さ2・平均節点 | 1277.625 | 1277.625 |

固定深さで全32局面の着手/評価/節点/評価回数が一致。速度比1.125017倍（時間約11.1%減）。同100msの節点は約30.5%増。この32局面は効率診断であり、一般的な速度保証や棋力向上の証明にはしない。原位置・全観測は本人限定で保存する。

## 検証と次の実対局

新3検査は駒取り/成り/駒打ち/通常局面の固定深さ一致、timeout復元と両視点の値、千日手/連続王手を確認。新arenaの実worker検査は同じNNUE tensorを先後両側で使い、backend表示/親保護/全棋譜再生/研究pointer非変更を確認。

D26の固定400局が完了してから、同じ第15周NNUEの全再計算対差分計算を新16序盤の先後32局・100ms・総512手・4CPU workerで実行する。これは統合/故障/時間の有界screenで、32局の勝ち越しを安定した棋力差とは認定しない。全親を事前monitor保護し、既存400局と合算しない。結果から正式採用を自動決定せず、速度利益と不具合/未決着/条件を記録する。
