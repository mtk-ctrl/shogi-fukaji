## 目的・事前に固定する試験

1. **新規1000局**：D37対D37、通常1手200ms、長考1秒は各陣営最大10回、C++ NNUE・静止探索0、最大512手。D37の旧train、D39 pilot、D40比較、D41の40局train、D42の50評価親を除外。1000異なる6手開始序盤を固定し、各棋譜を合法再生、状態（詰み・厳密引分・未決着）を区別。
2. **独立20GitHub Actionsランナー**で生成。各waveは20 jobs×各10局=200局、計5wave×200局=1000局。5waveは順番に実行し、同時に使う独立対局ランナーは最大20。再開checkpoint、各wave/ジョブの成果物、1000局すべてのparent ID・SHA、合法性・時計を監査。GitHub Releaseに原棋譜・条件・receiptを公開し再ダウンロードSHA一致。
3. **D37/Adam2106から直接学習**：1000局中の確定決着だけを教師とし、未決着は結果教師にしない。許可済み過去trainはreplay、旧評価/テスト群は混入させない。結果75%＋凍結親TD25%、lambda0.8、1局最大32局面、暫定2epoch、学習率0.0002（D41の0.001より抑える）。学習前snapshot・optimizer、学習後の重み・optimizer・全学習出所・損失をSHA付きReleaseに保全。損失低下を棋力向上とみなさない。
4. **新たな評価用100序盤×先後交替200局**：D37学習前と1000局学習後の両者を同一探索条件・CPU・時間制御で直接比較。学習親・過去比較親を除外。20実Actionsランナー×各10局。全200局の棋譜合法性・未決着・実着手時間・ペア単位の不確実性を検証し、結果をGitHub Releaseへ保存。事前に固定した実務上の勝ち越し閾値（例：勝数差12以上、未決着10局以下）とペア単位区間を併記し、優位が不明なら現行D37を保持する。
5. 正式NNUE重みの更新は学習前後の比較を通過した場合だけ。ほかの探索仕様・USI既定などを無断変更しない。GitHubを全データの単一正本とし、Driveへ新規二重保存しない。公開repoの通常ランナーのみを使用する。
