# 深路D16：NNUEを中核に据える独立強化路線
更新：2026-10-31
状態：**現行の優先研究方針（計画確定、D16実装・新実験は未着手）**

## 1. 本人の訂正と目的

本人の発言：「今深路の強化？雲路の強化？ 2つは別の道を歩んで強化させてるのよ？ 同じことをさせるのはかなり丁寧に検討してよ？ 深路はNNUEを最大限生かしたいのよ。探索の効率化はアリだけど、盤面評価に組み入れるのは、雲路から持ってくることにはならないはずよ。」

**対象は深路 `mtk-ctrl/shogi-fukaji` のみ。** 雲路は別系統の独立AIとして変更せず、比較と一般的な探索効率の着想に限り参照する。雲路の評価関数の重み、手作業の玉周囲配点、戦略・研究手・局面知識、教師用評価値・PVを深路の盤面評価へ移植しない。双方が似た課題（玉の安全等）を解くのは許されるが、解法の由来と学習方法を区別する。

深路の盤面評価は **NNUEに自己対局から獲得させる方向を優先**。評価特徴の表現は深路側で独立に設計・学習・検証する。探索の高速化（合法手生成、探索順、盤面更新、時間管理等）はNNUEでより多くの局面を読めるようにする横断技術として、**深路固有の条件で**検証する。雲路の実装を無条件に移植しない。

## 2. 現状：NNUEは研究段階、正式エンジンは別

- 正式エンジンは **FUKAJI v0.1.0**。高速合法手生成FastLegalGuardのUSI既定ONを正式採用済み。G8学習モデルは研究用の線形評価であり、**NNUEではない**。通常USIの初期設定はモデル未指定。従って深路を起動するだけでNNUEが動くとは説明しない。
- 実装済みの研究基盤：`fukaji/nnue_research.py` に **2548入力→32隠れユニット→評価出力**、二視点の差分累積器・合法盤面push/popと元評価の復元テスト。学習器は `nnue_train_research.py`。モデルと教師は深路の自己対局由来。
- D6-3の最初のNNUEは凍結train665局（4epoch、学習率0.005、32ユニット、各16局面）で学習した。元train/validation/testのlog lossはNNUE **0.6719 / 0.6663 / 0.6687**、G8 **0.5374 / 0.5934 / 0.5370**。条件差（NNUE新規初期化4epoch、G8旧モデル継続学習）を含み、NNUE一般の優劣ではない。
- D6-5は手番偏りを避ける隣接2手番サンプルでNNUEを再学習。新しい自己対局400局の詰み224局・34,884局面のみでのlog lossは G8 **0.5917**、元NNUE **0.6793**、隣接NNUE **0.6754**。隣接サンプルは改善したがG8に未達。未決着176局は勝敗ラベル化していない。この**評価済み400局は今後のモデル選択・学習・新規独立試験に再使用しない**。
- 計測済みNNUE差分push/popは通常盤面push/popの **約8.1〜8.3倍**（3固定局面、合成重み、shared CI）。累積値読取は約0.005ms/回。学習の精度と、探索中に一手ごとに重くならない実装の両面が課題。D6-2の細分プロファイラ実装は過去に安全チェックで拒否され、**その拒否を別経路で回避しない**。

根拠：[D6実測と限界](NEXT_EXPERIMENT_D6_20261030.md)、[NNUE開発履歴](NNUE_INCREMENTAL_EVALUATION_RESEARCH_PLAN_20261028.md)、[サンプル偏り監査](results/nnue_sampling_audit_20261030.json)。

## 3. 今後の研究順序（雲路の手作り評価は持ち込まない）

### D16-A：学習の収束と教師・分割を改善する

最初は **NNUEの学習過程が十分な更新を得ているか** を自分のtrain群だけで調べる。現行4epochと同じ初期値・学習率・局面抽出で、train損失、勾配の大きさ、更新量、過学習傾向と先後対称性を記録。モデル容量・学習率・局面抽出・epoch数を一度に変えず、1要因ずつ事前指定する。validation/testを何度も見て調整することは禁止。後で必要な評価群は**新しい自己対局seed・親群単位に分離**して新設する。

今回の大目的は「学習させたNNUEがG8より自己対局の未知の勝敗を予測できる」「同じ200ms探索で強くなる」。訓練損失だけを成果としない。

### D16-B：NNUEの特徴表現を独立に発展させる

現行の特徴は駒種・配置・持駒が中心。**玉の周りの敵駒配置や味方守りなどの相互作用**をNNUEが学びやすくするには、例えば玉からの相対位置を含む学習可能な特徴表現を新規候補として比較できる。ただし、これは雲路の安全度の配点を持ち込むことではない。重みは全て深路の自己対局データから学習させ、手作業で「危険升1つにつき何点」と決めない。

先にAの収束・データ診断結果を踏まえ、特徴追加・隠れ層ユニット数・学習方法のうち**一つだけ**変更した候補をつくる。外部AIや雲路の評価値・推奨着手を教師にしない。

### D16-C：NNUEの差分更新・推論を探索速度へ結びつける

二視点累積器の更新費用が大きい。安全性を保つ仕組み（持駒、成り、打ち歩詰、王手、千日手、棋譜履歴、push/pop逆操作）を壊さず、余計な全合法手再検査や持駒全閾値スキャンの再計算を減らせる可能性を調べる。速度比較は同一runner・同じ局面と探索コストで行う。過去拒否された変更は再試行・迂回しない。実装が許された別案を選ぶ。

### D16-D：学習済みNNUEと正式v0.1.0探索を接続して棋力確認

候補が独立保持群の予測損失・推論時間・正当性をクリアした場合に限り、研究専用ON/OFFでG8とNNUEの評価器だけを差し替える。共通条件は正式採用のFastLegalGuard ON、同一探索・同じ200ms指定・同一CPU、同じ開幕の先後交替。まず20組40局の問題検出→別seed120組240局で勝率・未決着・深さ完了・時間超過・評価損失を記録。**新たな研究候補の正式採用は別途本人の判断を必要とする。**

現行線形G8の単なる進化版ではなく、学習済みNNUEを正式評価器へ採用できるところまで進めることを主要な目標にする。一方、NNUEより強いと実証されるまでは現行正式版と研究G8を検証基準として維持する。

## 4. 探索と評価の独立性・相互依存（2026-10-31 概念監査）

本人の基本理解：「着手の探索の効率化と、そのたびに判断する評価値の再強化は、それぞれ独立」。**開発モジュールと単一要因実験を分ける理解として正しい**。ただし「相互に関連しない」という意味まで広げると不正確であり、棋力の最終性能は強く結合する。

- **設計の分離**：探索部は将来局面を生成・選択、評価部NNUEは状態から局面価値を返す。検索アルゴリズムの最適化は雲路を含む一般知見を参考にできるが、深路で独立した実装・回帰検証を行う。評価モデル自体・重み・手作業の戦略係数を雲路から持ち込まない。
- **計算コストの結合**：NNUEの一回の評価コスト、累積器push/pop・復元、評価を行う頻度と探索するノードの組合せで、同じ200msの到達深さが決まる。学習によって値の正確さを上げても計算が重くなれば棋力に不利になり得る。NPS・損失単独ではなく、同時間の棋力を評価する。
- **探索判断の結合**：静的評価の値/尺度は探索の候補順序、αβ枝刈り・静的枝刈り・時間配分などの閾値や判断に影響し得る（どれが現行深路に実装済みかは必ずソースで個別確認）。NNUEモデル変更時に旧閾値を当然視しない。
- **学習データの結合**：自己対局を使ってNNUEを訓練すると、探索の強弱・定跡・失敗傾向が教師棋譜の分布を左右する。NNUEが改善すると次の自己対局の分布も変わる。親対局単位で訓練・評価を分け、未決着を勝敗教師にせず、過去の独立評価群を後日の学習・調整へ混入させない。
- **将棋ルールの境界**：合法手・王手回避・詰み・千日手・打ち歩詰は探索/ルール処理で厳密に扱う。NNUEは有利不利の近似評価を行うが、ルール・詰み証明器の代わりとはしない。
- **NNUE固有の重要な設計**：入力特徴を玉基準などへ発展させたとき、指し手による変更特徴の数も変わり、差分更新費用が増減する。新しい特徴・モデル容量・学習条件の変更と探索側の最適化を実験では混ぜず、採用の直前には同じ実時間・合法性・新規先後交替実戦で組み合わせ全体を確認する。

結論：**研究は探索系／NNUE学習系の2本柱に分ける。ただし共通のインターフェース（評価値の向き・尺度、差分更新・履歴整合性、時間計測）と最終の棋力評価は必ず連結する**。雲路との共通化は一般的な探索の原理までとし、深路の学習済み評価・データ由来の独立性は保つ。

参考：公式Stockfish NNUE技術解説（インクリメンタル累積器と評価費用）、Stockfish探索実装（静的評価が枝刈り判断に反映される例）。これは一般的な構造の参考であって、深路がStockfishの全探索方式を採用済みであるという意味ではない。

## 5. 雲路と深路の共通化を認めるためのチェック

同じ技術を深路へ導入する前に、少なくとも次を文書化・検証する。

1. **目的の境界**：合法手の正しさ／探索の計算効率／時間管理か、評価関数・戦略・教師信号の持込みかを区別する。
2. **由来**：技術原理は一般的か、雲路独自の重み・研究成果に依存するか。雲路の評価値、研究筋、局面知識、戦略係数を教師やNNUE入力値へ移さない。
3. **独立性**：深路側で独立実装・テスト・比較し、両AIが結果的に同じ手を選んでも直接模倣を目的にしない。
4. **実益**：NNUEの精度・同時間の探索深さ・新規実戦棋力のいずれに改善があるかを確認する。
5. **保存先**：深路のコード・ルール・決定は深路repoにのみ反映。雲路のコード・設定・採用済み評価に変更しない。
