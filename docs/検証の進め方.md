# 検証の進め方（時間の優先順位）

決定：2026-11-10（ユーザー指示）

## 考え方
- 検証にかけた時間は、ほかの教科・作業にかけられた時間の損失。強さの確かめを厚くするほど良い、ではない。
- 数学・統計学の厳密さを目的にしない。目的は、次の一手を決められる程度に方向がわかること。
- 「たまたま勝ち越しただけかも」と疑う状況（差が小さい・基準すれすれ）でだけ確かめる。明らかな優位（例：+40以上／200局）が出たら、追試せずに先へ進む。
- 差が出ない・ほぼ同等のときは、速度・保守性・コストが小さいほうを採り、追加の検証をしない。
- 強化の方法が見つかりにくい今は、検証の厚みより「次の強化策を試す回数」を優先する。

## 運用ルール
1. 最初の対局（200局程度）で方向が決まるなら、そこで次へ進む。基準すれすれ・方向が割れるときだけ再確認する。
2. 追試を、ユーザーの作業時間をふさぐ形で積まない。必要な追試は、強化の作業と並行して流す。
3. 事前に決めた基準（親に+12/200局など）は、「候補にするかの足切り」であり、採用前の追試の回数を増やす理由にしない。
4. 正式採用は、これまでどおりユーザーの明示的な指示後。
5. 対局条件は本人指示の「通常200ms＋各陣営1秒長考10回まで」を標準とする（2026-11-10時点で、E2〜H64/H128の多くは長考なしの200ms固定で測定。`scripts/usi_match.py pair --longthink-ms 1000` で長考を適用できる）。
