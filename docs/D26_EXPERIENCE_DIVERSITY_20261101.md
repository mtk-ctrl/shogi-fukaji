# D26：新しい経験の開始局面を広げる有限1周

[D26 Goal](https://www.addness.com/goals/a6087494-f088-4a3a-b957-31b79d10608f)。D24の固定400局は安定強化を示さず、D25は旧経験保持と直近適応のトレードオフを診断した。比率の微調整だけを繰り返さず、各更新の経験の多様性を増やす。

## 変更と固定条件

- D25固定200局と全再生が終了してから実行する。研究親は第14周2161b2ba/optimizer1300。D25の比率候補は親14周と比較していないため、その勝ち越しだけで置き換えない。
- 既存の1周あたり2開始親/4train局を、16開始親/32train局へ増やす。半分は検証済みtrainの終盤継続、半分は新6手序盤。先後交換・歴代凍結NNUEの相手群を保つ。
- C++ NNUE/q0、50ms、最大追加256手、75%実結果＋25%凍結親TD(λ=.8)、2epoch、lr=.001、棋譜数で最近:旧50:50を保つ。未決着を教師にしない。monitor/audit親を再使用しない。
- 既存online_cycleを使う有限1周、第15周のみ。研究用暫定pointerと正式採用を分離する。候補・旧親・optimizer・棋譜・抽出seed・比較結果を全保存。
- batch増加に伴い総学習位置とoptimizer更新回数も増える。D25の固定16stepとの純粋な因果比較とは扱わず、経験batchを大きくした研究サイクルの実証とする。

## 検証と次の判断

32局の決着率、開始親数、学習境界以降の位置数、旧再生のユニーク数、更新量、実時間を確認する。既存の4局故障screenと少数周期比較は強化証明に使わない。全新train/monitor棋譜を合法再生し、candidate保持と再開索引を確認する。崩壊/未決着不足/保存不整合なら継続更新を止め診断し、候補は保全。

新候補の棋力判断は、結果を見て局数を延長するのでなく、親14周と初回学習済み等への新独立序盤・条件・必要精度・固定endpointを別に計画する。正式採用は本人判断。

## 実行と見積り

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m fukaji.online_cycle cycle --root build/d24-state --cycles 1 --pairs 16 --movetime 50 --max-plies 256 --epochs 2 --native-backend --quiescence 0
```

第12〜14周はtrain12＋monitor20の計32局で268.508秒。第15周はtrain32＋故障4＋周期最大24＝最大60局、同じ50ms/C++で単純換算約503秒。大きなbatchの学習/全再生/保存は別工程として実測する。待ちが同じターンに収まらない場合だけ、実際に開始した後の終了見込みに単発確認を置く。1時間等へ無根拠に水増ししない。
