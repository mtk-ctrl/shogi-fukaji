# 深路：小型NNUE型・差分更新評価の独立研究設計（2026-10-28）

状態：**設計のみ**。ニューラル評価の実装・学習・速度実測・対局・正式採用は未実施。雲路mainと深路USI既定探索は変更しない。

## 目的と比較対象

現行G8は`RelativeValue`の**手番相対2549特徴の線形評価**で、NNUEではない。固定200msのαβ探索を維持し、評価器だけを変更して、(1) 勝敗予測損失、(2) 1評価の時間、(3) 着手適用・復元時の差分更新の時間、(4) 同時間探索節点/完了深さ、(5) 独立実戦勝敗を順に切り分ける。探索法のUCT研究とは同時変更しない。

## 既存実装の確認

- `fukaji/learning.py` の `FEATURES = 81×14×2 + 2×7×20 + 1 = 2549`。盤上駒と持駒の閾値化したone-hot、最後の1は切片。
- `fukaji/relative_value.py` は盤面を手番視点に反転し、盤上81升と持駒を走査して線形重みを合計する。学習済みG8 SHA `18b39f647caa458389a1900b875337adadac74ae37e27343e7f0094ed663c492`。
- `fukaji/engine.py` の`evaluate_relative_fused`は古典評価と線形評価を1走査にまとめる高速経路。NNUE候補の比較ではこの実装を速度の対照とし、意図せず旧遅い経路へ戻さない。

## 最初の候補（事前固定）

1. 入力：2548個の既存手番相対特徴（切片は別bias）。隠れ層32ユニットの小型全結合、活性化は0〜1へ切り詰めたReLU、出力は1個のlogit。float32、有限値検査、モデル形式・SHA・seedを固定。これは**独自のNNUE型試作**で、他AIの評価重みや探索コードを取り込まない。
2. 差分更新：手番が変わるたびに全特徴を作り直すと増分の意味が薄い。**先手視点と後手視点の2本の隠れ層累積値**を持ち、着手で変化した駒の出発/到着・成り・取った駒・持駒閾値を双方に加減算する。評価時は現手番の累積値を読む。局面と差分状態を同じスタックでpush/popし、例外時も復元。
3. 安全性：盤上・持駒・手番・SFEN・合法手・王手・詰み・打ち歩詰・千日手・成り・駒打ち・捕獲の各ケースで、差分累積値と**盤面からの全再計算**を比較（許容誤差を明示）。着手列・逆順popで完全一致。NaN、重み形状不一致、SHA不一致は拒否。
4. 学習：G8の既存830詰み原本と固定957親群分割を**再利用**。学習665局（旧459＋新206）だけで重み更新。検証81・テスト84局は更新やハイパーパラメータ選択に使用しない。未決着142局と長考の変更手は教師にしない。本人の対局以外の人間棋譜・外部AIの評価/推奨手も教師にしない。初回の隠れ層32、学習率、epoch、seedは検証結果を見る前にPLANへ固定し、試行錯誤の後出し選択を避ける。
5. 評価の比較：同一データ・同じ分割のG8線形評価とのlog lossを別々に記録。探索の評価値スケールと古典評価の混合比を固定し、モデルだけを差替え。固定局面で全再計算・差分更新・G8高速線形の推論時間と、αβ同200msの探索量/合法性を測る。NNUE型の実装だけで高速化や棋力向上を主張しない。
6. 独立実戦：固定局面と単体テストが成功し、速度/品質の候補性が確認された場合のみ、親群・序盤seedを学習から独立させた先後交替240局。未決着を勝敗/引分へ変換せず、ペア単位の統計も併記。採用判断は本人。

## 実装を小さく分ける

- A：特徴インデックスと**全再計算**による32隠れ層の推論・形状/非有限値テスト（USI本体へ接続しない）。
- B：2視点累積値のpush/pop差分更新と合法局面/反復/持駒の一致検査。
- C：固定親群の学習器・学習/検証/テスト損失・SHA付きモデルartifact。
- D：G8固定αβでの評価器差替え・速度診断、候補性があれば独立実戦。
