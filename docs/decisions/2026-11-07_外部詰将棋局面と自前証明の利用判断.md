# 2026-11-07：外部詰将棋盤面と雲路の自前詰み技術を深路で利用

## 本人判断と誤認の訂正
本人発言：「いや外部詰将棋は盤面をもらっただけで詰み筋をもらったわけじゃないから、詰みに関してはそのまま使えるところ使っていいと思うよ。」

従来AIが「雲路の詰み学習予測器は外部詰将棋から学んだから深路に移植しない」と一括して除外したのは、局面提供と正解着手教師を混同した判断だった。**外部盤面の利用は深路の独創性と矛盾しない。** 詰みはルール上の勝利条件であり、局面から自分で証明する。

## 現行repoで確認した根拠
- 雲路 `benchmarks/tsume_dataset/mate3_1000.sfen` 等のサンプルはSFEN盤面の列であり、着手手順列はない。[manifest](https://github.com/mtk-ctrl/shogi-ai/blob/main/benchmarks/tsume_dataset/manifest.json) には公開元・採番seed・SHAがある。**ただしmate3/mate5といったファイル分類は外部の詰み手数情報を含む**。これを「一切の解答ラベルがない」とは表現しない。
- 雲路の[10万問採用記録](https://github.com/mtk-ctrl/shogi-ai/blob/main/docs/decisions/2026-10-11_詰み10万問学習モデル正式採用.md)では、約10万局面の詰み有無を雲路の自作7手以内探索で判定したと明記。学習済み16特徴予測器は**詰みの証明器ではなく、詰み探索の優先判断用**。
- [雲路MateSearch](https://github.com/mtk-ctrl/shogi-ai/blob/main/engine/strategy/mate_search.h) は王手の合法候補と受方の全合法応手から詰みを証明。[MateAssist](https://github.com/mtk-ctrl/shogi-ai/blob/main/engine/strategy/mate_assist.h) は攻方短詰みと相手の詰みを確認する。
- 一方[雲路MateLearning](https://github.com/mtk-ctrl/shogi-ai/blob/main/engine/strategy/mate_learning.h) の16特徴には手作業の玉周辺情報・駒得を含み、雲路の評価器に依存するため、予測器全体を無検証で深路のNNUEに接続することは避ける。詰み探索の時間配分・優先順位だけに独立利用する研究は認める。
- 深路にも既存の[研究用1/3手詰み証明器](https://github.com/mtk-ctrl/shogi-fukaji/blob/main/fukaji/mate_oracle.py)と[研究用MateAssist](https://github.com/mtk-ctrl/shogi-fukaji/blob/main/fukaji/d4_mate_assist.py)がある。**正式C++ NNUE/USIには未結線**。既存成果を踏まえて重複開発を避ける。

## 対象と禁止の境界
**使えるもの**：外部SFEN、詰み専用の自作探索アルゴリズム、合法手の生成・王手と全応手の検証・王手回避の安全性判断、詰み専用の補助器（学習時の詰みは自前証明）、有限時間内の詰み探索予算配分。元データの再利用・公開範囲は配布条件を別途確認する。

**そのまま混ぜないもの**：雲路の一般的な駒得点・玉安全の手作業配点、人間の定跡や他AIの好手・評価値・PV、人間棋譜を正解着手教師とする仕組み。詰み予測器の人手特徴は**一般の局面評価NNUEには投入しない**。詰み探索だけの補助器として検証し、詰みを予測だけで確定しない。

## 次の工程・成功条件
1. 深路の既存研究用mate_oracleと雲路MateSearch/MateAssistを比較し、深路のC++合法手・履歴・時間制限へ適合する最小実装を研究版に作る。1手→3手→5手、次いで7手、相手の詰み回避を検証する。
2. 外部SFENの出所・配布条件と問題の重複を確認し、学習用と未見評価用を固定。全合法応手で詰み手順を独立証明し、未証明は UNKNOWN として扱う。
3. 必要なら雲路の詰み予測器や時間配分を詰み**補助専用**として単独比較する。NNUE重みD45を固定し、詰み検出率・処理時間・実戦勝率を既存探索と比較。
4. 結果が改善した場合のみ正式探索への採用を本人に提案。今回の発言は**研究上の再利用許可**であり、現行NNUE重み・正式探索仕様の即時変更ではない。
