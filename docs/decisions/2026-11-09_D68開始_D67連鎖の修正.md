# 2026-11-09 D68開始とD67→D68連鎖の不具合修正

## 確認したこと
- 正式NNUEはD66／Adam11864（snapshot c29b5ba1…）。D67 run 42527107929 のステップ1〜15（200局監査の検証、全テスト、main CAS、正式D66のcommit、公開Release・SHA再取得）は成功。採用は有効。
- 同runのステップ16（D68後継の生成・起動）だけが失敗。run全体は failure 表示だが、採用結果とは別問題。

## 原因（2件、いずれもD68生成器 scripts/d68_codegen.py）
1. 生成した `d68_games.py` などに行末空白・末尾空行があり、後段の `git diff --cached --check` が終了コード2で止まった。
2. `d68_arena.py` の置換順の誤り。親D66報告の検査 `parent_report["schema"]!="d66-learned1000-v1"` が、後続の子側置換（d66→d68）で部分文字列一致し `d68` に壊れた。D68初回起動 run 42540495634 は事前検査で失敗（対局・学習は未実行）。

## 修正
- 生成時に行末空白を正規化し、子側置換を先に行うよう順序を修正。
- D68生成物をD66の検証済み状態から再生成し、workflowの事前検査（契約検査、構文、スキーマ検査、`--help`、1手詰み証明）を手元で通過させた。
- 入力は D67 と同一：snapshot c29b5ba1…、Adam11864、推論SHA e8b9eec6…、学習 9a046de9…、原1000局 9e711baf…、200局監査 0c98b8bc…、source run 42471868758。

## 範囲
- D68は有限の1回：1000局＋学習＋学習前後200局。NNUE重みのみ更新、USI v0.4.1とPVS＋詰み探索は不変。
- 採用はD66対D68の200局が事前勝差の基準を満たした場合のみ。満たさなければD66を維持。
