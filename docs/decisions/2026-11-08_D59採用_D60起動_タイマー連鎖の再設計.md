# D59採用からD60強化、タイマー連鎖の定義と実行記録（2026-11-08）

## F01原文に沿ったタイマー連鎖
1. 次の具体的な工程（NNUE正式採用CI／1000局自己対局runなど）を実際に起動する。
2. その実行ID・各波の実測・残り局数・queue・集計・保存所要を使い、終了見込み時刻を計算する。
3. 同じ会話で最後まで確認できない場合のみ、終了見込みに対応した**単発**確認を予約する。予約できる実時刻との差は別記。
4. 予約が発火したらrun全ページ・終了結果・GitHub Release SHA・モデルと200局の全棋譜を照合し、採否判定とmainへの原子的な正式採用を実行、ただちに次の1000局を開始して**次の単発予約まで実際に作る**。作業中なら測定し直して単発を更新する。

**タイマー発火＝連鎖の成功ではない。** 登録／発火／結果取得／次の工程開始／次の予約の各段階を、証拠とIDで別々に判定する。根拠のない毎時定期処理を設定しない。無限・無条件のGitHub Actions連続ループは禁止（F30の有限実行・明示起動）。
