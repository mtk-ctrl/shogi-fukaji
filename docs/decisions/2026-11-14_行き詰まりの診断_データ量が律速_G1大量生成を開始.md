# 行き詰まりの診断と方針: 律速は学習局面の量。G1(大量生成)を開始（2026-11-14）

本人指示（2026-11-14「提案に沿って順番に進めてください」）。

## 診断
- 直近の不採用3件（自己対局再学習 約2.4万局面、10秒ラベル 約4.6万局面、玉相対/玉周辺特徴 約6万局面）は、どれも学習局面が数万。唯一大きく伸びたE10（対E9 83-17）は約11.5万局面で教師も更新した回。
- ラベル付けが1局面2〜10秒と高価。深くしても伸びない（10秒ラベルで43-56）ので、深さより数に計算を回す。
- 評価の速度は律速ではない（実測・1局面・2秒）: ハイブリッド(E10)は約138万節点、雲路本体の評価は約74万節点。NNUE評価は探索時間の約25%（gdbサンプリング28点中7点、粗い）。差分更新の上限は約1.3倍なので後回し。

## 進める順番
1. **G1 大量生成**: ハイブリッド(E10)の短時間自己対局（1手50ms、ランダム8手開局、定跡・局面知識なし）を20ランナー×全コアで回し、各局面の探索値と勝敗を記録。目標は数百万局面。`scripts/g1_gen.py` / `g1-gen.yml`。
2. **学習**: 親E10から現行特徴(base)で学習し、対E10ハイブリッド100局で判定。`scripts/g1_train.py` / `g1-train.yml`（疎行列で高速化。更新式は従来fitと同じ）。
3. **勝敗の比率**: 同じデータで outcome_weight 0.2 と 0.5 を比べる。
4. **見送った案の再挑戦**: 同じデータで玉周辺(zone)・玉相対(king)。その後、隠れ層256・両視点入力。
5. 差分更新は後回し。

## 境界
- 教師は深路NNUE＋借用探索の値と対局結果だけ。雲路の評価値・指し手・定跡は使わない。
- 正式モデルはE10のまま。採用は対局比較の結果を見て本人が判断。
- 手元の事前確認: 生成は1コア約20〜30局面/秒（30〜60ms）、学習は base 約3.6ms/ステップ・king 約19ms/ステップ（バッチ256）。棋力は未検証。
