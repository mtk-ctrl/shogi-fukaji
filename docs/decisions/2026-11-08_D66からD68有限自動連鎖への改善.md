# 深路：1000局タイマー連鎖の失敗からGitHub有限自動連鎖へ（2026-11-08）

## 目的
現行正式NNUEの自己対局1000局→NNUE追加学習→先後入替200局比較→改善時のみ正式NNUE採用→次の1000局起動を、ChatGPTの単発タイマーが結果報告で途切れる問題から切り離す。主眼は棋力向上と実runの無人連鎖の検証。F00/F01/F10/F20/F30準拠、Addnessは保留。20独立GitHub Actions runner、現行USI v0.4.1・PVS+合法詰み探索不変更。費用上限なしの無制限周回は許可しない。

## 失敗から判明した事実
- 11月8日のD58確認・D60監査・D62完了・D64完了に付けた複数の単発予約は、発火しても次の研究コード作成・採用CI実起動・次の単発登録を最後まで処理できなかった。**予約の発火・結果報告は連鎖ではない**。
- D60監査はproducer/collectorで異なる古いschemaを誤って要求し、元200局ジョブを保存できても最後の集計に失敗。成功済み棋譜を流用した有限の集計専用CIで救済。各新世代で親/子のschema対と元SHAを事前検査する。
- D61/D63/D65の採用は、会話から個別プログラム作成・実run開始後、GitHub Actions本番のUSI・原本SHA・完全Adam・リリース再取得に成功した。**GitHub Actions自体での後続処理は成功するが、単発予約の自然言語経由で新プログラム生成まで任せる構造が止まりやすい**。
- D66初回run [42471642729](https://github.com/mtk-ctrl/shogi-fukaji/actions/runs/42471642729) は `scripts/d66_arena.py` のprepare呼出しを閉じる `)` 抜けで対局前に停止。CIのPython構文エラーをGitHubログで特定、main `dd5ee01f25dbffa6777ae1225f0d9dfd1a080e3a` に修正し、同一研究requestを再push。**新1000局実run [42471868758](https://github.com/mtk-ctrl/shogi-fukaji/actions/runs/42471868758)** は19:32:39 JST開始、prepareとwave0全20ジョブ成功を確認した。旧失敗runを新1000局結果に合算しない。
