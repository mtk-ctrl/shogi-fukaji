# 評価値の目盛り2400と左右反転学習を採用（2026-11-15）

本人指示(2026-11-15「良さそうであれば作り込んで、自己対局で弱くなっていないか確かめてください」)。[点検記録](2026-11-15_手番の扱いの点検_評価値の目盛りと左右反転が未着手.md)の候補1・2を実装し、対局で確かめた。対局はすべてハイブリッド・1手200ms・54ペア108局・18並列。

## 1. 評価値の目盛り(1ロジット=何cp)：600→2400を正式設定に採用
- 同じE12の重みで 2400 対 600：66勝42敗(run 43664203966)。
- 4800 対 2400：45勝63敗(run 43664687284)。2400の両側で負けるので2400付近が良い。
- E12・2400 対 雲路：53勝55敗(run 43665043735。600のときは49勝51敗)。弱くなっていない。
- 変更: formal/model.json の hybrid.nnue_scale=2400。重み・探索コードは不変。
- 学習データとの整合: 生成時の目盛りを summary の nnue_scale に記録し、学習(g1_train.py)はその値で勝率に戻す。記録のない旧データは600として扱う。g1-gen.yml・hybrid-match.yml(scale=formal)は正式設定を読む。

## 2. 左右反転した局面を学習に使う：学習の既定にした
- g1_train.py --mirror。特徴番号の置換で反転局面を作る(盤の筋を反転、持ち駒は不変、玉周辺は横の差を反転)。実際に盤を反転して作った特徴と約1万局面で一致を確認。
- 周回3と同じデータ(生成run 43657376230、親E12)で学習(run 43664202193)。検証損失 0.57381→0.57252(反転なしは0.57285)。
- 反転あり候補 対 反転なし候補(run 43663127867、周回3の候補)：64勝43敗1分(run 43665377613、目盛り2400)。
- g1-train.yml の mirror 既定を true にした。

## 3. 両方を合わせた強さ（反転あり候補＋目盛り2400）

- 対 雲路：72勝36敗(run 43665729056)。E12は49勝51敗、周回3の反転なし候補は56勝44敗(いずれも目盛り600)だった。
