# 自己対局の運用を一本化する（特徴を変える実験の扱い）

- 日付：2026-11-19（本人の指摘：周回で正式採用が起きると、旧版と新版が混ざらないか）
- きっかけ：距離帯特徴（入力3848→4784）の学習をE23を親に始めた直後、周回でE24が正式採用された。E23親の候補をそのまま採用すると、E24の改善が消える。

## ルール
1. **正式な系統は1本**。親は常に formal/model.json の hybrid節（その時点の正式版）。
2. **特徴の形を変える実験（入力数が変わるもの）は、周回とは別の枠**。起動時点の正式版を親に作り、**対局を始める直前に、親がまだ最新の正式版か確認**する。最新でなければ破棄し、新しい親で作り直してから対局する（古い親との対局結果は判定に使わない）。
3. **採用の窓口は1つ**（hybrid_nnue_adopt.py）。学習報告の parent が現在の正式版と一致しなければ採用しない（既存の検査）。入力数が現行と違う候補は、このスクリプトでは採用できない。
4. **特徴の形が変わる採用**は、周回を一時止めて切り替える。周回の学習（g1_train.py）は、親の入力数が違うと止まる作りのため、採用と同時に g1-train.yml の feature_set の既定を新しい形に変え、その間は周回の新規起動を保留する。
5. 実験の起動・結果・採否は、この `docs/decisions/` に残す。複数のチャットが同時に動くため、起動前にmain最新と実行中のActionsを確認する。

## 距離帯特徴の扱い
- 実装（Python・C++・学習の選択肢 band、PythonとC++の評価値一致検査）はmainに入っている。既定は変更なし。
- E23親の学習（run 44517219748）は、親が古くなったため判定に使わない。
- 次：このルールどおり、E24（現行の正式版）を親に、距離帯特徴で1回だけ学習し、対局直前に親を再確認して108局で現行と比べる。
