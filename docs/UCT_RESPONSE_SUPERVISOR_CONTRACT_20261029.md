# 深路UCT：応答監督と探索ワーカー分離の軽量契約（2026-10-29）

状態：**研究専用・未採用・既定OFF**。USI接続、実ワーカー生成、G8実測、対局、学習、雲路main、深路正式USI・モデル・既定値を変更しない。[前段の境界監査](UCT_HARD_DEADLINE_ARCHITECTURE_REVIEW_20261029.md)を前提とする。

## 「200ms」の異なる三つの契約

1. **USI応答**：`go`受信から`bestmove`標準出力への実送信まで。合法fallback準備、応答準備、書込み確認を別時刻で記録。標準出力への書込みと外部GUIへの到着は同一ではなく、flush/GUI受信を含むなら別途定義する。
2. **探索関数**：`select_mcts`呼出しからreturn後の関数フレーム・探索木解放まで。関数内部のelapsedだけを全体時間と呼ばない。
3. **資源終了**：ワーカー停止確認、探索木・IPC資源解放まで。①が期限内でも③が完了したとは限らない。

一般的なPython/共有OSでは①も絶対200msの硬い保証にはならない。OS停止、IPC遅延、出力ブロックの最悪値を保証できない。目的は①の**実用上の期限超過率低減**の候補設計であり、②③の達成を偽装しない。

## 純粋な契約モデル（実USI未接続）

`fukaji/uct_response_contract.py`は外部依存のない**単一スレッドの状態遷移モデル**。実プロセス、タイマー、stdout、将棋合法手判定は実装しない。監督側が測った単調時刻を注入し、ワーカー自己申告時刻は信用しない。

- `go`受信時刻から200msを数え、**合法手列挙とfallback準備も時間に含める**。検証済み合法手の順序付きsnapshot、局面識別子、世代IDを固定。0反復でも先頭の合法手を返せる。合法手0件のときのみ`resign`。
- 候補更新は世代ID・局面ID・事前に検証した合法手集合・監督側受信時刻が期限前である場合のみ受理。旧局面・期限後・不正手・応答準備後は拒否。SFENだけでは千日手等の反復履歴を表せないため、合法手snapshotは**正本の履歴付き盤面**から作る必要がある。
- 応答の準備と送信確認を別操作にし、準備だけで送信成功と記録しない。送信後の重複応答を拒否。fallback準備が200msに遅れた場合は期限達成と記録しない。
- ワーカー停止は応答送信と独立に記録。応答後の残留ワーカー、終了確認遅延、ゾンビ・FD・メモリ残留は別検査。別目的のActions runを止める機能はない。
- `stop`、`ponderhit`、複数`go`、IPC競合、実送信、強制停止・例外時fallbackは**未実装**。未送信の応答がある間の再入は拒否。未決着を勝ち・引分教師にしない。
