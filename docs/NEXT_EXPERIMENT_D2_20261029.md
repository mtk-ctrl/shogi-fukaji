# D2：同じ総200msで合法手列挙の重複を削減できるか

状態：計画確定、実装・実測未実施。強化軸は深路の**探索高速化**。D1は深さ上限を広げても深く読めず、呼出全体の超過が増えたため、次は単一律速に限定する。正式USI・モデル・既定値・採用は変更しない。

## 問いと比較の公平性
同じG8モデル・同じ合法局面・同じ総200ms・同じ深さ上限6で、既定OFFの`FastMoveList`相当の単一走査合法手列挙だけを有効にすると、合法性・着手選択を壊さず完了深さが増えるか。

D1は探索の内部期限がroot準備後に始まり、Bの超過96/96だった。D2はA/B**双方に同じ研究用の呼出開始期限**を適用し、root準備も200msに含める。この共通時計変更はD1とは別の基準と明記し、D2の差分は合法手列挙ON/OFFだけにする。厳密OS応答保証を実装する工程へ拡張しない。

## 入力と計測
- 固定G8 SHA256 `18b39f647caa458389a1900b875337adadac74ae37e27343e7f0094ed663c492`、既存240局 SHA256 `60eb9ab4dadc3776e43ac49cf27bd04137477c339850fdaa7db2265248a8d3bf`。既存D1と同じ48独立親局面をSHA固定manifestから再利用する。開発診断用で未見試験ではない。
- mix25、高速相対評価ON、root α再利用ON、上限6、200ms総予算、同一runner。A=従来合法手列挙、B=単一走査（既定OFF）。ABBA順で、合法性・反復履歴・完全深さ・節点・root準備・内部探索・呼出全体・200ms超過を記録。
- 先に少数固定局面を時間無制限の同一深さでA/B比較し、手・節点・評価が一致すること、王手中・打ち歩詰・持駒・千日手に退行がないことを確認。違えば実測へ進まない。
- 実測では同時間内に完了した深さの改善、合法手・指し手の退行、超過、計算量を比較。着手差や節点数だけで棋力を断定しない。

## 進行・停止基準
1. 共通期限起点と`FastMoveList`差分を研究専用既定OFFで実装し、軽量テスト→PR→branch CI→研究main→main CI。
2. 27repo5状態と同目的重複を実取得確認し、明示request1runnerで最大48局面ABBAを実測。モデル・原本・manifest・出力SHAと合法性を監査し、requestをOFFへ戻す。
3. 有意な完了深さ改善・同時間条件・合法性が成立すれば、戦術局面の有界検証→40局故障検出を別計画。改善しなければ最大の処理律速（合法手/終局判定/評価）をプロファイルし、次の一つだけ削減する。
4. 探索整備だけで2工程連続して棋力につながる実測へ進めなければ研究単位を縮小し、静止探索・評価NNUE・攻守詰みの独立軸へ移る。新しい240局の対局は改善候補の時間・戦術・合法性が通ってから事前固定する。
