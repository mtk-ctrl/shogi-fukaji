# D1：深路の深さ2制限が着手品質を妨げているか

状態：計画確定、実装・実測未実施。研究専用。通常USI・モデル・正式採用を変更しない。

## 問い
同じG8評価・同じ実時間予算で、深さ上限2を6へ広げるだけで、余った時間を有効に使い、戦術の見落としが減るか。改善がなければ、静止探索または処理量不足の仮説へ移る。

## 固定条件
- 基準コード：`e065af72546e20aa7c0e193fc24f37a8b057e8a7` の `fukaji/engine.py`。
- G8モデルSHA：`18b39f647caa458389a1900b875337adadac74ae37e27343e7f0094ed663c492`。
- G8/G7既存240局：run40637486947、集約JSONL SHA `60eb9ab4dadc3776e43ac49cf27bd04137477c339850fdaa7db2265248a8d3bf`。モデル取得元はrun40636602223。
- mix25、高速相対評価ON、root α境界再利用ON。Aは最大深さ2、Bは6。それ以外の研究フラグは元対局に合わせる。設定を実行記録へ書く。
- 既存比較240局はこの実験では開発診断用。新しい未見試験と呼ばず、学習教師にも入れない。

## 工程
1. 小さな研究専用診断スクリプトを用意。既存取得・合法再生コードを再利用し、原本を勝手に上書きしない。旧版Aの再現を先に確認。
2. 48独立親ペア以下から局面選定を凍結。序盤・中盤・終盤・王手/持駒の戦術局面を目標各12とし、親ペアと盤面重複を排除。抽出順・seed・分類優先順を結果を見る前にmanifestへ記す。不足を人工局面で埋めず件数として報告する。
3. A→B→B→A、同一runner・同一局面・200msで計測。呼出前から復帰後までの総時間と内部探索時間を分け、root準備、完了深さ、節点、途中中断、合法代替手、局面・反復履歴の復元を記録する。
4. 初回のA/Bは上限だけを変更した診断とする。既存のroot準備時間が予算外になる問題でBが余分な時間を使う場合、棋力の同時間比較へ進めない。必要なら共通の期限起点・中断確認だけを修正した別基準を作り、A/B双方に同じ修正を適用して測り直す。厳密OS保証を作る工程へ拡張しない。
5. 詰み/取り返し/王手回避等の少数固定回帰を、独立した有界全幅検証または合法な詰み証明で確認。深い探索との手の一致だけを正解扱いしない。
6. 合法性・復元・終局・時間の退行がなければ40局の先後交替試験を設計し実行。明白な退行なら停止。有望なら次の独立240局へ進む。

## 完了基準と分岐
- 入力実体・設定・選定manifest・A/B全観測・集計が揃い、結果を読み戻せること。
- Bが深く読めた局面数、同時間内の手の改善/悪化が証明できた件数、不明件数、時間超過を報告する。
- Bが深く読めない：合法手/終局/評価の負荷を調べ、最大の重複処理一つを削減する。
- Bが深く読めるが戦術見落としが残る：静止探索を次の独立候補とする。
- Bの戦術・時間が良好：固定G8との40局へ。勝ち越しだけで正式採用しない。
- 2工程続けて基盤だけを増やした場合は、ROADMAPの目的に戻して研究単位を縮小する。

## 予算・見込み
最初のスクリプト実装と既存CI確認は45〜90分の作業見積り（実測ではない）。最大48局面×4回×200msは探索本体約38.4秒相当だが、root準備・原本再生・導入・集計を含まない。Actions起動後、実際の準備時間と進捗からETAを更新する。速度計測は1runnerで順序交替、対局はR21に従い空きへ分割する。
