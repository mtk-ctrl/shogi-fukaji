# 深路UCT：有限実OS子の重複・旧世代拒否・私設flush遅延（2026-10-29）

状態：**研究専用・既定OFF・未採用**。雲路main、深路正式USI、G8モデル、既定値、学習・対局へ接続しない。

## 目的と測定境界

従来の `LiveProbeSession` は合成資源台帳に旧世代を残せたが、実OS子プロセスが複数同時に存在したことは検証していなかった。今回の `fukaji/uct_os_overlap_probe.py` は固定コードのみを実行する有限の子を2つ起動し、**異なる実PIDが同時に `Popen.poll() is None`** である瞬間を観測する。旧子を残したまま監督モデルの次世代へ進み、旧子からの候補が旧世代として拒否されることを確認する。正式USIでの並列探索ではない。

- 子は固定JSON候補を1行書いてflushし、協調 `stop` を最大1.2秒だけ待ち、30ms後に自然終了する。引数配列で `sys.executable -m fukaji.uct_os_overlap_probe --child` のみ起動。任意コマンド・shell・信号・強制終了・外部run停止なし。
- 親は旧世代で私設 `bestmove` を送信・確認した後、**旧OS子をまだ回収せず**次世代を開始する。各子の実pipeから受けた候補を親の単調時計で記録し、旧世代の候補を拒否する。実OS子の回収と合成台帳での `resources_released` は別の観測。
- 親の予定応答時刻と、私設pipeへ書込み・flushした実時刻との差を記録する。`flush` は正式USI stdout送信やGUI受信の証明ではない。少数観測から遅延分布の上限や硬い200ms保証を主張しない。
- 協調停止は自分が起動した2子にだけ送る。`wait(timeout=2)` で回収を試み、失敗なら未回収と記録する。強制終了で安全制限を迂回しない。回収済みでもOS全体のFD・メモリリークゼロは証明できない。
- 合法手は固定の信頼済みテスト入力 `('7g7f','2g2f')`。実盤面・履歴付き合法性の検証は既存 `uct_legal_snapshot.py` の範囲であり、本試験は棋譜合法再生ではない。

## 軽量検証
