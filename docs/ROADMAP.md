# 深路 FUKAJI 自己進化エンジン 実装ロードマップ
策定 2026-10-26。これは実装計画であり、未検証の達成を意味しない。

## 理想
深路自身の対局から価値評価、有望手、探索効率を学び、未知の局面でも強くなり、固定基準版・雲路と同条件で棋力向上を立証する。

## 不変の境界
- 雲路 mtk-ctrl/shogi-ai のmainと正式知識は変更しない。
- 将棋ルール・USI・探索を移植するときは元commitを固定し、やねうら王由来のGPL-3.0や通知を保持する。
- 外部AIの評価値・PV・推奨手は教師にしない。外部AIは棋力の測定相手とする。
- 実験世代の自動昇格と正式版への採用を区別する。
- Actionsの計算予算はリポジトリ間で共有されることを前提に監視する。

## P0 基盤の信頼性
現状: NumPy線形value v0、python-shogi合法手ランダム対局、詰み/勝者検証、棋譜単位split、Actions入口。push検査成功、実学習workflow未検証。
- 特徴量・手番視点・持ち駒のテスト強化
- 終局事由・勝者・ラベルの厳密な検証、未決着を勝ちにしない
- dataset/model hash、seed、分割重複監査、成果物再取得
- workflowを実際に1度起動して完走・モデル出力確認
完了: 実際に学習と未使用検証が走り、再現性と入力合法性を示せる。

## P1 独立した深路エンジン
- 雲路特定commitから合法手/USI/最小探索/手作り評価を必要最小限で移植
- GPL通知とビルド再現性を保持
- USI時間・合法手・王手・千日手・合法終局のテスト
- ランダム生成器を本物の深路エンジンによる自己対局へ置き換える
- 各棋譜にエンジンSHA、seed、先後、時計、知識ハッシュ、終局情報を記録
完了: 独立Actions上で真正な深路同士の完了対局・監査・データ保存が成立。

## P2 学習するニューラル評価器
- 小型NNUE型の局面表現とCPU推論を独立実装し、200ms制約下の速度を測定
- 勝敗由来valueと自身の探索由来targetを区別し、単純な自己評価の模倣を避ける
- 対局・同型局面群単位でtrain/validation/test分離
- モデル重みを深路エンジンへ接続し、従来評価との混合率をAB検証
- 勝率・nodes・深さ・推論時間・未見データ損失を比較
完了: 学習した重みが実際の指し手へ反映され、同条件の実戦比較が完走。棋力が劣れば研究候補に留める。

## P3 自動世代循環
- collect -> audit -> train -> validate -> arena -> promote/reject -> next の状態機械
- 各世代の親SHA、学習棋譜、モデルhash、学習設定、計算予算、比較seedをmanifestへ固定
- 再実行に耐える冪等性、途中失敗の再開、データ重複・計算枠の防止
- 旧世代・固定基準世代・異なる候補と競争させる
完了: 手操作なしで研究世代2サイクルを完走し、候補の採否とデータ・モデル受渡しを再現。

## P4 重点局面と指し手学習
- 重大悪手、評価変動、不確実局面、好手、静かな対照を層化抽出
- 開始局面と反復履歴を保った複数候補手の分岐対局
- 分岐結果からvalueと指し手優先順位モデルを個別に学習
- 旧局面replay bufferと普通の局面も混ぜ忘却を防ぐ
- 機能ごとのON/OFF比較で寄与を測定
完了: 未見局面の実戦性能改善を立証。効果がなければ撤回。

## P5 大規模強化
- 小型/中型モデルを同一200msと予算で比較
- 探索予算の動的配分、歴代強モデルとのリーグ、必要ならMCTS系の独立比較
- 外部相手は教材でなくベンチマークとして使用
- 学習効率・Elo・予算のPareto最適化

## 全段階で守る検証
- 先後交替・同じ序盤局面ペア・固定seed・同じ200ms・同じ追加長考条件を原則とする。
- 初期100局程度は探索的試験、確証評価は必要精度に応じ事前に局数と停止条件を固定する。95%信頼区間・Elo推定を併記。
- 固定基準世代に対しても勝率を追跡し、近い世代への過適合を検出する。
- 失敗時は棋譜/ラベル、モデル、推論速度、探索接続、対局条件の順に切り分ける。

## 直近の実装順
P0実学習の起動確認 -> P1移植元固定とライセンス確認 -> 深路自己対局 -> P2小型ニューラルモデル -> 実戦比較。
先に『データ収集→学習→実際に指すエンジンへ反映→棋力確認』を1周通す。
