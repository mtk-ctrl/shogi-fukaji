# D37　本人限定の20ランナー実行案

研究用 `7d74b86b`／Adam 1850 と正式版 `e0cbd2ab` で新100序盤の先後200局を生成する。20ジョブに各5序盤・10局を割り当てる。固定条件は双方50ms、静止探索0、追加256手まで。200局の合法手と終局を照合し、決着局と過去棋譜を使い1回学習する。正式版との採用判断用比較は別工程。

作業環境切断前に、実データから固定100序盤を準備し、事前計画との一致、20×10、ワークフローの非公開ガードを確認した。短いネイティブ動作試験の終了結果は取得できなかった。このブランチには作業内容をコードとして再構成して保存した。ブランチ版の動作試験、GitHub Actions本走行、学習、成果物保存は未実施。

## 再開

1. 本人のみがアクセスできる専用の非公開実行先、使用可能な20並列枠、費用上限、Actions起動権限を確認する。公開リポジトリに入出力データを置かない。過去の公開先送信に対する自動審査の拒否は[D20](../../docs/D20_RELIABLE_RESUME_AND_TARGET_TRIAL_20261101.md)を参照。
2. [D36停止済み再開点](../../docs/ROADMAP.md)を別作業領域へ復元。依存導入後、リポジトリ直下から `./run-research.sh research/d37-private-selfplay/run.py prepare --root RESTORED --package PRIVATE_INPUT` を実行する。出力は計画のSHA256。生成したフォルダには非公開の重みを含む。
3. 同一コードを非公開実行先に置き、このYAMLを `.github/workflows/` に配置する。本人限定の経路で入力を同じ非公開リポジトリの `d37-private-input` artifact として登録し、登録元のrun IDと計画SHAを指定して起動する。入力登録経路とその権限は別途確認する。計画SHAとエンジン・スクリプトSHAはワーカーで検証する。
4. 実行した20ジョブと稼働数を記録する。同じrunの全出力を本人限定のローカル領域に取得し、`shard-N/result.json` の構造で置く。スクリプトの `verify --root RESTORED --package PRIVATE_INPUT --plan-sha SHA --results RESULTS` で200局を照合し、同引数の `train` で単一書込みにより学習する。
5. 最終状態は既存の上限256 MiBを超える可能性がある。原データを保全した可搬保存方式の検証を済ませ、本人限定Driveへ保存して再取得・復元・候補とAdamを照合する。
